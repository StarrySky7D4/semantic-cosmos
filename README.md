# 新闻语义宇宙 · v0.4.0

这是一个可部署到 GitHub Pages 的本地语义工作区。随包提供完整前端源码、Rust 数值核心源码、编译好的 WASM、中文 ONNX 模型、原始新闻 JSON、512 维真实向量和静态构建产物。没有远程计算服务或 API 密钥。

## 在线展示

https://starrysky7d4.github.io/semantic-cosmos/

`main` 分支更新会自动运行测试、构建并部署至 GitHub Pages。

## 立即运行

从 GitHub 克隆或下载源码后，先执行以下命令生成 `dist/`：

```sh
npm ci
npm run build
npm run serve
```

`dist/` 是构建产物，不提交到源码仓库；完整离线发布包则包含预构建的 `dist/`。

直接打开 `dist/news-cosmos.html`，可以查看新闻、旋转缩放、搜索、调整参数、在真正的 WASM 核心中重建层级和关系，以及导入/导出带向量的 JSON。这个单文件已经嵌入原文、默认向量、图谱 Worker 与计算 WASM。

要运行文本嵌入模型，在本项目根目录执行：

```sh
npm run serve
```

用浏览器访问终端显示的 `http://127.0.0.1:4173`。此命令只需要 Node.js，不需要安装 npm 依赖。点击左侧「用本地模型重新嵌入」，或者导入仅有 `items` / `texts` 的 JSON。模型与推理运行时从随包静态文件加载，运行期间无需外网。

Pages 部署时，把 `dist/` **里面的内容**放入你的 Pages 发布目录，保留 `.nojekyll`、`assets/`、`models/`、`vendor/`、`wasm/`、`data/`、`licenses/` 和 `sw.js` 的相对关系。支持 GitHub 项目子路径，不需要根域名部署。仓库提供 `.github/workflows/pages.yml`：推送到 main 或手动触发时，安装锁定依赖、运行数值与几何测试、构建 dist、检查模型哈希及相对路径，再发布到 Pages。GitHub 仓库需设为 public，并在 Settings → Pages → Source 选择 GitHub Actions。工作流只授予构建所需的读取权限，以及部署所需的 pages/id-token 写入权限。

## 数据与默认设置

- 原始文件实际有 29 个 `items`，虽然 `meta.item_count` 标注 28。全部条目均被保留，原文件没有改写。
- 元数据窗口为 2026-08-31 至 2026-09-30。4 条窗口外内容作为背景保留，可在目录上方筛选。
- 原始 ID、日期、类别、实体和出处链接保留在记录和图谱导出中。
- 日期筛选只改变可见节点与目录，全库统计不变。
- 不对新闻内容、价格、发布名称或出处有效性作独立事实核验；它们是用户提供的待组织语料。
- 根数量 4；平均连接切割阈值 0.72；跨根候选阈值 0.72；树内 kNN=4；每叶主题最多 2 条跨树边；小簇目标最小大小 2；虫洞最长 0.65D；主题相关性下限 0.45；聚集强度 0.80。D=225 是固定空间基准距离。
- 根大小和主题粒度来自向量，不强求均衡。少于最小大小的整棵根树仍保留。

模型为 `Xenova/bge-small-zh-v1.5`，固定 revision `75c43b069aac4d136ba6bc1122f995fedcfd2781`，Q8 权重，CLS 池化与 L2 归一化，最多 512 tokens，输出 512 维 FP32。输入是 `title + 。 + summary`。预计算默认向量采用**实际浏览器单线程 ONNX/WASM**输出，减少本地原生推理与浏览器推理的差异。模型和原始文件的哈希记录在 `dist/data/`。

## 已实现

1. 中文真实嵌入；CPU/WASM 为已验证路径。WebGPU 是可选后端，需要在目标设备单独验证；失败时可以手动选择 CPU。
2. Rust/WASM 归一化、K-Means、精确平均连接、带权微簇平均连接、同根 kNN 和跨根候选扫描。
3. 阈值切割后，将小簇并入平均相似度最高的相邻簇，再重建主题层级。主题内与跨主题关系分别保存。
4. 每个主题各自为局部球心；相似主题中心更近。文本按叶主题相关性加权定位，以聚集参数增强局部密集性，同时保留共享与离群内容。虫洞同时受相似度、长度与每叶主题数量限制。
5. 主题目录、原文查看、来源链接、日期筛选、参数重建、JSON 与 FP32/FP64 NPY 导入。
6. Worker 内计算、任务取消；模型每 4 条保存嵌入检查点。重新提交完全相同的内容和后端，会复用已完成部分。
7. IndexedDB 工作区快照与持久存储请求；完整 JSON 导出作为独立备份。
8. 同源 Service Worker 缓存页面和使用过的模型资源。页面成功加载后可离线重新打开；第一次运行模型需要本地服务器或已部署站点提供资源。

根名通过文件中的 6 个主题定义与根中心匹配得到；子主题名称来自代表文本。名称是探索辅助，未调用 LLM 定义主题，不是经人工标注验证的分类结果。三维拟合无法完全保留高维距离，跨树边仅为相似度候选。

## 多球心与密集空间的几何规则

- 根、分支和叶主题各自为局部球心，自由分布在三维空间。主题向量为成员归一化中心。球心间目标互斥距离为 `D * (0.075 + sqrt(2 - 2*cosine)) * (1 - 0.4*density)`，D=225，density∈[0,1]。越相似，目标距离越小；相同主题仍留小间距，避免完全重合。这是软约束，不保证所有主题球互不相交。
- 三个确定性初值拟合主题对距离，选择加权应力最小的结果。根对权重 4、根与子主题权重 2、其他主题对权重 1。只将整体平移到原点附近，不限制各球心到原点的距离。`metadata.space.fitRmsNormalized` 记录拟合的加权均方根误差 / D。高维距离无法在三维完全保真，也不能保证每对主题的排序都严格保持。
- 文本与全部叶主题计算相似度，再对超过相关性下限的最强 3 个主题加权。参考叶主题可避免层级中重复的宽主题中心多次吸引同一文本。权重为 `max(0,(s-floor)/(1-floor))² * exp((s-best)/0.07)`；文本初始位置为球心加权平均。
- 令主次权重差为 `dominance=1-w₂/w₁`；聚集拉力为 `density*dominance`，将加权位置进一步拉向最相关球心。有明显主题归属的文本更紧密；两个主题同等相关时拉力为零，仍处于两球心之间。均匀相关内容没有特殊的全局球心落点。
- 从全库拟合三个共同的语义投影轴，将文本与最相关主题中心向量的残差作为小范围局部位移。位移随聚集强度增加而缩小，并受局部球半径约束；相同文本表示不会被随机拆散。
- 每个主题的局部球半径结合成员语义分散度、最近主题间距和聚集强度计算，最低 8 个空间单位。球表示邻域尺度，可以重叠，也不强制包含所有目录成员。共享文本可离开其主归属球。显示球跟随展开层数，隐藏局部球不会影响坐标。
- 对全部参考主题低相关的文本保留为离群点；提供定义主题向量时，还以定义作范围检查。离群位置在全部局部球外围，与每个球表面至少相隔 1.2D。方向使用稳定种子，代表未能定位，不声称有语义方位。阈值需按实际语料校准。
- 虫洞先按文本端点三维长度过滤，随后保留各叶主题对的最强候选并应用数量上限。最长默认 0.65D，独立于各球半径。折叠后继续检查替代端点的长度，隐藏过长连线；使用直线。导入图谱的过长虫洞也会移除并提示。
- 聚集强度只改变空间布局，不改变目录层级、文本归属和向量。位置变化可能使一条虫洞通过或未通过长度限制。旧图谱可保留原坐标查看；有向量时点击重建即可应用新布局。

## 当前边界

- 精确构建限 2–400 条文本、2–4096 维；已有图谱导入限 5000 节点、30000 边。
- 不长期保存 N×N 相似度矩阵。根内层级会分配临时工作表，精确扫描仍有平方算量；不是十万条数据的 ANN 实现。
- 小 LLM 精分、ANN、语料向量 FP16/INT8/PQ、增量 ANN 更新和跨设备同步尚未实现。模型权重的 Q8 与语料向量量化是不同事项。
- 原始文本 ID 保持不变；主题节点 ID 只在本次构建及其快照中有效。更换模型、后端或阈值可能改变分支。
- 标签页关闭后任务不持续运行。保存的嵌入检查点可恢复，但完成的模型输出仍需重新构建图谱。
- 浏览器存储可能被清理，持久存储申请也可能被拒绝；请导出快照作为备份。
- 页面 URL 与项目路径变化时，需要重新建立本地快照和缓存。

## 重新构建

需要 Node.js 20+：

```sh
npm ci
npm run build
npm run check:pages
npm test
```

修改 Rust 核心时，先安装 Rust 并添加 target，再编译：

```sh
rustup target add wasm32-unknown-unknown
npm run build:wasm
npm run build
```

`COSMOS_RUSTC` 可指定编译器路径。本次已提供 `public/wasm/cosmos_core.wasm`，仅改前端不必安装 Rust。

重新生成原生 CPU 参考嵌入：

```sh
npm run embed
npm run build
```

原生 ONNX 后端可能与浏览器量化算子存在数值差异。生成与浏览器路径一致的默认嵌入：

```sh
npx playwright install chromium
npm run embed:browser
npm run build
npm run test:browser
```

如使用已有 Chromium，可通过 `COSMOS_CHROMIUM` 指定可执行文件。`scripts/fetch-model.mjs` 可重新下载同一固定 revision 的模型；默认构建不需要下载模型。

## 验证与文件位置

完整离线发布包中的 `verification/results.json` 保存端到端结果，包含实际浏览器推理、预计算/重算一致性、WASM 重建、JSON 往返、快照恢复、嵌入检查点、离线重新加载和手机布局检查。截图位于发布包同目录，源码仓库不包含这些历史截图；`tests/core.test.mjs` 包含已知向量平均连接、边分数和图谱结构检查。

数值核心在 `wasm-core/src/lib.rs`，构图在 `src/core.js` 与 `src/graph.worker.js`。球心拟合与亲和度定位在 Worker 内的 `src/space.js` 中执行，Canvas 负责显示；这部分是 JavaScript。模型 Worker 在 `src/inference.worker.js`，本地保存位于 `src/storage.js`。
