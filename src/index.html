新闻数据 → 本页的可运行流程

01 / REPRESENTATION文本 → 单位向量

使用 BGE-small-zh-v1.5 的 Q8 权重，CLS 池化与 L2 归一化；输出 512 维 FP32 向量。

02 / FOREST粗分 → 局部层级

Rust/WASM 执行 K-Means 与平均连接；提供的主题定义只用于给根命名，不强制决定归属。

03 / CONNECTIONS近邻 → 稀疏虫洞

kNN 只在同根内取边；跨根单独扫描，先过滤过长连线，再按叶主题限额筛选。

04 / SPACE主题球心 → 密集邻域

球心自由拟合随余弦相似度变化的互斥距离。文本按最相关的叶主题加权定位，并向明确主题聚集；共享内容位于主题之间。

已经实现的边界

  • 余弦评分使用归一化向量，不使用 Ward 连接。
  • 先按阈值切割层级；小簇并入平均相似度最高的邻簇，再以带权平均连接重建主题层级。
  • 虫洞取跨根文本相似度，每个叶主题最多 0–4 条；最长默认 0.65D，不设最低条数。边按无向关系去重。
  • 层级边、树内近邻、跨树虫洞分别保存；原文与稳定 ID 独立保存。
  • 精确构建限定 2–400 条；超过 400 条自动使用分层语义分区，最多 20000 条。每个精确近邻单元最多 32 条，屏幕同时显示最多 600 节点（窄屏 240）。

本页接入中文 ONNX 嵌入和 Rust/WASM 数值核心；大库由星云、星系、恒星系、资料行星组成，选中行星后展示来源卫星。分层构建支持最多 20000 条；没有接入小 LLM 或 ANN。网页默认载入预计算目录，详情与来源按需读取；通过 HTTP / Pages 运行时可以重新嵌入。

嵌入接入与数据格式

可以导入带向量的单个 JSON，或者分别导入 texts.json 与 vectors.npy。NPY 支持二维 little-endian FP32 / FP64，C 或 Fortran 顺序；不接受 pickle 对象。

{
  "texts": [
    {"id":"doc-1", "title":"标题", "text":"原文"},
    {"id":"doc-2", "title":"标题", "text":"原文"}
  ],
  "vectors": [[0.1, 0.8, 0.2], [0.3, 0.1, 0.9]]
}

维度与条数必须一致、数值必须有限、向量不得为零。浏览器不会把文本上传到任何服务。真实数据的根名默认是“根主题 n”；本页不冒充自动生成主题定义。

设计建议 / 未接入推理后端

可选：表示压缩与规模扩展

归一化嵌入的相似度矩阵满足 S = EEᵀ。保存 E 即可按需求 Sᵢⱼ；不必长期保留 N×N 相似度表。

  • 先以稀疏 top-k 图替代全量缓存，再验证 FP16 与降维。
  • 降维需要模型明确支持，或固定并版本化投影；重新归一化并重测阈值。
  • INT8 需正确处理 scale、zero-point 与范数；量化召回后可用高精度向量复核。
  • 大规模构建采用分块、微簇或 ANN；跨主题召回保留独立通道。

400 条以内保留精确平均连接；更大语料使用固定语义分区与最多 32 条的局部精确近邻，不创建全库两两矩阵。可能漏掉跨分区关联，尚未引入 ANN。JSON 导出是便于查看的交换格式，并非压缩二进制格式。

有向 top-k CSR / u32 ID 与偏移

CSR = N·k·(4 + 分数字节数) + (N+1)·4。若总边数超出 u32 范围，必须改用更宽行偏移；缺失边表示未保存，不表示相似度为零。
